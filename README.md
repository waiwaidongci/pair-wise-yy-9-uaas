# 曝光批次与冲洗联审台

在「古法蓝晒底片整理室」基础上扩展为**曝光批次 × 冲洗联审**工作台。规则、存储、展示三层分离：

- `src/domain.js` —— 规则层（纯函数）：必填校验、药液批次占用、结论失效、复晒闸门、状态与统计推导
- `src/store.js` —— 存储层：JSON 落库、旧数据迁移、写操作全局串行化、复晒幂等
- `src/view.js` —— 展示层：联审台页面
- `server.js` —— 入口：仅做 HTTP 路由编排

## 运行

```bash
npm start        # http://localhost:3040
npm test         # 规则单测 + HTTP 端到端测试（node --test）
```

数据保存在 `data/joint-review-station.json`（首次启动自动播种；旧版底片数据会自动迁移）。
可用环境变量 `JOINT_REVIEW_DB` 覆盖存储路径、`PORT` 覆盖端口。

## 业务规则

- **必填项**：登记批次必须含尺寸、曝光时长、冲洗水源、显影结果，缺项返回 `400`，不可提交。
- **药液批次独占**：同一药液批次只服务一个未结束（未入盒）曝光批次；冲突返回 `409 chemical_batch_busy`，且**绝不落库**。入盒后药液释放，可再开新批次。
- **显影结论失效**：冲洗水源变化或曝光补时，显影结论立即失效：
  - 未入盒 → 退回「待复核」；
  - 已入盒 → 保留盒位、标记「受影响」，药液不重新占用。
  - 失效后复晒计数从最近一次失效起重新累计。
- **复晒双人确认**：复晒复核须由另一人确认（确认人 ≠ 复核人，否则 `409`）；连续**两次**密度合格且无边缘不均才可入盒，否则入盒返回 `409 cannot_box`。
- **重复 / 并发沿用首次**：复晒提交带 `requestKey`，同一 key 的重复或并发请求只落第一条，后续返回首条结果（`reused: true`）。
- **一致展示**：卡片、状态与统计均由同一份存储实时推导，刷新后一致。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/batches` | 批次列表（含推导状态、复晒进度） |
| GET | `/api/batches/:code` | 单个批次明细 |
| GET | `/api/stats` | 状态统计（与列表同源） |
| POST | `/api/batches` | 登记曝光批次（冲突 409 不落库） |
| POST | `/api/batches/:code/reviews` | 复晒复核（双人确认，`requestKey` 幂等） |
| POST | `/api/batches/:code/water` | 变更冲洗水源（触发结论失效） |
| POST | `/api/batches/:code/extra-exposure` | 曝光补时（触发结论失效） |
| POST | `/api/batches/:code/box` | 入盒（闸门通过才允许） |
